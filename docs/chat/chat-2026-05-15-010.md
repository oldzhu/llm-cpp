# Chat Session 2026-05-15 — MoE (Mixture of Experts) Implementation

> [简体中文](#聊天会话-2026-05-15--moe-混合专家-实现)

## Summary

Implemented Mixture of Experts (MoE) FFN as an optional MLP type. `--mlp moe` CLI flag. Router with top-K gating, multiple expert FFNs, and auxiliary load balancing loss. Checkpoint version 4.

## What Was Done

### 1. MoE MLP Implementation
- `src/variants/moe/moe_mlp.h` / `.cpp`: `moe_mlp_forward(x_2d, w_router, b_router, expert_params, n_experts, top_k, interm_dim)`
- Router: softmax(x @ w_router + b_router) → gating scores
- Top-K: keep K experts per token, renormalize
- Expert FFNs: independent GELU MLPs, computed only for routed tokens
- Weighted combination: y = sum_k gate[k] * expert_k(x)
- Load balancing loss: n_experts * sum(f_i * P_i) to encourage uniform usage

### 2. Model Integration
- Config: `mlp_type = 2` (MoE), `n_experts = 4`, `top_k = 2`
- Block: `moe_router_w/b` + `moe_expert_wfc/bfc/wout/bout` per block
- Total params per block: 18 (base) + 6 (SwiGLU) + (2 + 4*n_experts) (MoE)
- `moe_balance_loss_` accumulator, added to main loss with 0.01 scale
- `--mlp moe` CLI flag

### 3. Checkpoint v4
- Save with version=4
- Load v1/v2/v3: MoE params initialized to zeros (backward compat)

### 4. Tests
- `test_moe_forward_produces_output()`: Validates shape, finiteness, balance loss
- `test_moe_training_loss_decreases()`: 30-step training with MoE model

### 5. Bug Fixes
- Rewrote MoE forward to use `nn::matmul2d` directly (avoided reshape+linear_lastdim chain)
- Vector reserve in test to prevent pointer invalidation

## Verification
- `ctest -C Debug`: 20/20 tests pass, 0 failures, 0 warnings
- CLI training with --mlp moe: loss 6.09 → 5.46 over 20 steps
- All previous features unaffected

## Design decisions
1. MoE uses raw matmul2d (avoids reshape chain issues with nn::Tensor views)
2. Load balancing lambda = 0.01 (soft auxiliary loss)
3. Default n_experts=4, top_k=2
4. Expert FFNs are independent (no weight sharing)
