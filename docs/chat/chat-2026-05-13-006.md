# Chat Session 2026-05-13 — CPU SIMD Blocked Matmul Backend

> [简体中文](#聊天会话-2026-05-13--cpu-simd-分块矩阵乘法后端)

## Summary

Implemented a blocked matmul CPU backend with AVX SIMD intrinsics. This is Stage B (CPU performance) of the CPU→GPU progression in the project lifecycle guidelines.

## What Was Done

### 1. BlockedSimdCpuBackend
- `src/backend/blocked_simd_backend.h` — Header
- `src/backend/blocked_simd_backend.cpp` — Implementation:
  - **Blocking**: BM=64, BN=64, BK=64 tile sizes
  - **Packing**: Panel packing (A and B reordered for contiguous access)
  - **Micro-kernel**: AVX `__m256` FMA (fused multiply-add), 8 floats per instruction
  - **Remainder handling**: Scalar fallback for non-multiples of 8
  - **Backward**: dA += dC @ B^T and dB += A^T @ dC, same blocked pattern
  - **No-AVX fallback**: Scalar blocked matmul if AVX not available

### 2. Tests
- `test_blocked_simd_matches_cpu_matmul()`: Compares SIMD fwd/bwd output against CPU reference for 6 size configurations (16-256 dims, including non-multiples)
- `test_simd_backend_via_model_training()`: Runs 20-step training with SIMD backend; verifies loss decreases

### 3. Build system
- CMakeLists.txt: Added `blocked_simd_backend.cpp` to `llm_core`

## Verification
- `ctest -C Debug`: 15/15 tests pass (2 new SIMD tests)
- `cmake --build`: 1 minor warning (unused fallback function)
- SIMD backend produces **bit-identical results** to CPU reference at 1e-4 tolerance

## Design Decisions
1. Block sizes: 64×64×64 (fits L1 cache for 3 panels)
2. AVX __m256 with FMA intrinsics for the inner kernel
3. Separate packing and micro-kernel phases for clarity
4. Backward reuses the same micro-kernel with transposed data layouts
5. Compile-time AVX detection (HAVE_AVX macro); scalar fallback otherwise
